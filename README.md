# Личный Health OS на Vercel

Самостоятельная версия схемы health-os-workshop: загрузка анализов и заключений, история показателей с графиками, рекомендации врачей, напоминания и чат по медкарте.

Оригиналы и структурированные записи хранятся в private Vercel Blob. В репозиторий не попадают документы, токены и пароли. Каждая запись хранится отдельно; одновременная загрузка разных документов не перезаписывает карту. Повтор идентичного файла определяется по SHA-256. Пересчёт mg/dl выполняет код по справочнику воркшопа.

## Запуск

Node.js 24, `pnpm install --frozen-lockfile`, `pnpm test`. Развёртывание на Vercel из этой ветки. Секреты задаются в Environment Variables: OPENAI_API_KEY, HEALTH_PASSWORD, SESSION_SECRET, BLOB_READ_WRITE_TOKEN. OPENAI_MODEL по умолчанию gpt-4.1-mini.

## Что доступно

- Вход по паролю и подписанная HttpOnly-сессия на семь дней.
- PDF, PNG, JPEG, WebP до 3 МБ на файл, несколько файлов по очереди.
- Оригиналы скачиваются только после входа.
- Показатели и визиты выводятся из всех сохранённых записей, без учебного пациента.
- Экспорт JSON содержит разборы и свод. Оригиналы скачиваются отдельно из списка документов.
- Чат получает актуальную карту и последние три пары реплик текущего диалога. После перезагрузки переписка очищается.

## Ограничения первой версии

Интерфейс восстановлен из рабочей версии воркшопа: боковое меню, графики анализов, профиль и напоминания. Данные часов можно импортировать JSON в разделе «Сон и пульс»; используются последние 90 дней. Telegram-бот пока не перенесён. Скриншоты одного анализа загружаются отдельно. Напоминания на сайте извлекаются из рекомендаций; автоматической отправки нет. Большие файлы требуют отдельного прямого загрузчика в Blob. Разборы ИИ нужно сверять с оригиналами. Автоматический резервный архив вне Vercel пока не настроен — используйте экспорт и скачивание оригиналов.

Исходные промпт, схема разбора и справочник взяты из health-os-workshop. Сайт не ставит диагнозов и не назначает лечение.

## Ultrahuman

ULTRAHUMAN_API_TOKEN хранится только в Vercel. Синхронизация по кнопке или Vercel Cron раз в сутки около 10:00 UTC (CRON_SECRET). Последние 7 дней перечитываются, чтобы учесть поздний синк кольца. Оригинальные ответы API хранятся отдельно по датам в private Blob и накапливаются без удаления; интерфейс показывает последние 90 дней. Сон, HRV, температура и восстановление — только из кольца. Шаги кольца сохраняются как ringSteps и не считаются шагами Apple Watch; Apple Watch ещё не подключены. Аналитика считает средние по фактически доступным данным, без подстановки нулей.

## Активность Apple Watch

Отдельный раздел activity. Бесплатный ручной импорт стандартного export.zip / export.xml Apple Health. Архив читается локально через fflate, передаются только дневные сводки выбранного источника Watch и тренировки. Данные iPhone, Ultrahuman и других часов не суммируются, точные дубли отсеиваются. Дневные файлы activity/watch/YYYY-MM-DD.json обновляются без накопления повторов; хранятся все импортированные даты, интерфейс и экспорт свода показывают последние 90 доступных дней. Дни определяются по локальной дате начала записи из экспорта; частичные дни могут отличаться от итогов приложения Fitness. Прочие показатели здоровья, маршруты и сырые файлы на сервер не передаются. Автоматической передачи Apple Health пока нет.

## Автоматическая активность iPhone

На странице «Активность» добавлена настройка Health Auto Export (стороннее iPhone-приложение; автоматизации требуют Premium). Кнопки создают отключённые REST API автоматизации по одному показателю: шаги, расстояние, активная энергия, минуты нагрузки, пульс покоя. Пользователь разрешает чтение HealthKit, выбирает Apple Watch в Preferred Sources, затем включает и проверяет Export на iPhone. Автоматизации запрашивают отправку примерно раз в 2 часа; iOS не гарантирует расписание, при блокировке доступ к HealthKit ограничен.

`POST /api/activity/setup` требует сессию владельца и возвращает deep link с отдельным ключом отправки. Ключ хранится только в приватном Blob settings/activity-connection.json и передаётся в Authorization: Bearer на `POST /api/activity/receive`; он не открывает чтение медкарты. Не копируйте ссылку настройки в публичные места. Статус `/api/activity/status` доступен только владельцу.

Принимается JSON v2 Health Auto Export с data.metrics; каждый sample должен иметь явный source с Apple Watch. Анонимные/агрегированные записи пропускаются, при отсутствии подходящих записей возвращается 422. Выключите агрегацию и оставьте один показатель на автоматизацию. Не все версии iOS/приложения сохраняют источник в агрегированных данных; подключение считается проверенным только после реального успешного экспорта. Тренировки пока передаются ручным импортом.

Пакеты хранятся приватно по дате, показателю и хешу. Повторные и пересекающиеся отправки объединяются по времени и источнику, без суммирования разных часов. В интерфейсе показываются последние 90 дней. Сон и ночной HRV остаются из Ultrahuman. Изменение или удаление исходного sample в Apple Health не является командой удаления уже принятой истории.

## Семейные карты и Telegram

Общий вход — только вход в семейное пространство. Для каждого медицинского API дополнительно требуется подписанная HttpOnly-сессия пациента (12 часов), проверяется версия доступа в приватной конфигурации. Личные пароли хранятся как salted scrypt. Есть общий постоянный лимит попыток входа в приватном Blob с условными записями ETag. Общий пароль не заменяет личный пароль.

Изначально карты: Организатор, Член семьи, Питомец (собака). Начальные личные пароли генерируются вне Git, доступны владельцу в локальном access.txt. владельцу карты передаётся только её пароль. Организатор как организатор может создавать дополнительные карты (до 20), задавая их начальный пароль; чтение существующей чужой карты требует её личного пароля. После передачи начального пароля владелец карты может сменить его. Изменение пароля повышает version и отзывает прежние браузерные сессии и Telegram-привязки.

Медицинские обращения выполняются внутри AsyncLocalStorage-контекста пациента. Организатор использует существующие records/, originals/, settings/, activity/, wearables/ без перемещения или удаления прежних данных. Остальные карты хранятся в patients/<id>/. Общая конфигурация доступа — family/. Сырой Blob никогда не отдаётся браузеру без выбранной карты. Совпадающий SHA документа в другой карте не даёт доступа к его оригиналу. JSON-экспорт и OpenAI-контекст содержат только выбранную карту.

Кольцо Ultrahuman и существующий токен отправки часов закреплены за owner; пользователь запроса не может переназначить пациента. Для других карт кольцо не подставляется и вызов синхронизации закрыт. Свои дневные данные часов можно импортировать вручную внутри соответствующей человеческой карты. Питомец строит графики по ветеринарным документам: человеческие пороги из каталога отключены. Применяются лишь референсы документа, помощник получает вид пациента.

Один бот семейный Telegram-бот работает через POST /api/telegram/webhook, заголовок X-Telegram-Bot-Api-Secret-Token сверяется с TELEGRAM_WEBHOOK_SECRET. Бот отвечает только на личные сообщения, где chat.id совпадает с from.id. Telegram username и подпись сообщения никогда не дают доступ. Пользователь в разблокированной карте нажимает «Подключить Telegram»: сервер создаёт случайную одноразовую ссылку с TTL 10 минут; в Blob сохраняется хеш кода, погашение атомарно по ETag. Привязка сохраняет id+version разрешённых карт. Из общей семейной страницы без личного входа получить код нельзя.

Бот поддерживает /start, /help, /profiles (также /profile), /unlink. Разрешено подключить несколько карт (например, собственную и питомца) отдельными кодами. Перед вопросом применяется выбранная разрешённая карта; история по Telegram ID и пациенту хранится отдельно, последние 6 сообщений. При попытке выбрать чужую карту или callback без права доступ закрыт.

Документы: PDF/JPEG/PNG/WebP до 12 МБ через Telegram (до 3 МБ веб). Telegram передаёт webhook с file_id, затем сервер скачивает файл с ограничением размера и проверяет сигнатуру. OpenAI читает документ и имя пациента; имя лишь подсказывает кнопку, не выдаёт прав доступа. Подтверждение получателя обязательно. До подтверждения файл и разбор находятся в приватном family/inbox/<telegram-id>/ и не участвуют в медкарте; через 24 часа подтверждение недоступно. Просроченные неподтверждённые объекты не удаляются автоматически физически — очистку нужно запускать отдельно. После сохранения или отмены содержимое pending-объекта заменяется коротким статусом. Вид пациента должен совпадать. Неизвестное имя требует явного выбора. Документы и ответы передаются OpenAI, сообщения бота — Telegram, хранения на GitHub нет.

Обработка update_id имеет распределённую блокировку с TTL, повторные доставки не повторяют активную обработку. Документы внутри карты дедуплицируются по SHA256. Системного фонового планировщика Telegram-напоминаний в этой версии нет: бот принимает документы и отвечает на вопросы; напоминания доступны на сайте и по запросу.

Конфигурация Vercel: TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET и FAMILY_INITIAL_PROFILES — sensitive production env. FAMILY_INITIAL_PROFILES содержит только имена, вид и scrypt-хеши начальных паролей; используется для инициализации приватного family/. Устанавливать webhook после проверки развёртывания; секреты не выводить в логи и не включать в файлы сайта. Переподключение прежнего бота к webhook прекращает getUpdates на учебном сервере; регистрация нового бота не требуется.

Проверки: `node --test lib/*.test.mjs`; интеграционные — `node --experimental-test-module-mocks --test lib/family-api.integration.mjs` (только фиктивные данные в памяти, production не затрагивается).
